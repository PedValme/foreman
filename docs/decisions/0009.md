# 0009 · Outside Hermes, the reviewer is a fresh session Foreman launches

**Decision.** Outside Hermes the review is a new session of the same harness, launched by Foreman (never by the
writing agent), without tools, given the diff. The user picks its model and effort; with nothing picked it is the
same model one effort level up, and the verdict says so. It reviews when someone asks to merge; on every turn only if
the user turns it on, and only where the harness's end-of-turn hook waits for it.

**Why.** The verdict must not pass through the hands of the agent that wrote the code. A session that did not write
it, on another model or with more effort, is the closest each harness offers to Hermes's second model, and it runs on
the user's own subscription to that harness, so how much it spends is the user's choice.

**Alternatives.** Asking the writing agent to spawn a reviewer (the author controls the review). A fixed external
model API (a second account and credentials Foreman would have to hold).

**Consequences.** Nothing the author of the diff controls can become the answer: a schema the harness enforces, or a
seal made for that one request; an answer without it counts as "could not run". See `docs/rules.md`, rule 25.
