# 0008 · One core, an adapter per harness

**Decision.** The detector and the gate live once, in `plugin/foreman/`. Each other harness (Claude Code, Codex, pi,
OpenCode) gets an adapter in `adapters/` that only translates: what the harness sends becomes the gate's own calls,
and the gate's answer becomes what the harness understands. An adapter adds no gate rule and loosens none, and never
needs an edit in `plugin/`. What the core needs to know from its host it asks its context for, by names Hermes's own
context does not have (`foreman_host_label`, `foreman_review_before_merge`, `foreman_finish_review`).

**Why.** Two copies of the gate drift apart, and a user on another harness would get a different, untested promise.
Keeping `plugin/` free of adapter code keeps the listed Hermes plugin exactly what Hermes users run.

**Alternatives.** A port of the gate per harness (several gates to keep equal). A generic host for any agent
(nobody had asked for a harness the adapters do not cover).

**Consequences.** Outside Hermes, `/foreman` is the Hermes plugin's own board run unchanged on a stand-in for Hermes's
context. Foreman's program and state are files the agent's shell can reach there, so the adapters guard them; the
required check in CI stays the independent control (0011). See `docs/rules.md`, rules 22 and 26.
