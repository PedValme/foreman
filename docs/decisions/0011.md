# 0011 · In CI, the detector never comes from the checked repository

**Decision.** The check in CI (`action.yml`, or the workflow to copy in `examples/foreman-check.yml`) loads Foreman's
detector from Foreman's own folder (the action with an isolated `python -I`), never from the checkout of the pull
request it checks. In
the action, a finding marked `foreman:allow` fails the check by default (`strict`); the user can turn that off.

**Why.** Running `python -m foreman…` from the checkout let a pull request bring its own detector in a folder named
`foreman` and pass itself. And in CI, where nobody may review the pull request, a marker the agent wrote would
otherwise pass alone.

**Alternatives.** Running from the checkout (the hole above). `strict` off by default (the agent's own marker goes
through wherever no person reviews).

**Consequences.** In the action (strict), a legitimate marked finding needs its cause removed or an administrator's merge. Foreman in
CI is a lock only once the check is required, the workflows are protected, the rules bind the agent's own account and
Foreman runs in a job of its own (README, "In CI"). See `docs/rules.md`, rules 10 and 27.
