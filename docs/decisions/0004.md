# 0004 · A second model reviews, by default when someone asks to merge

**Decision.** An optional review of the diff by a model other than the one that wrote it: in Hermes, through the
host's own model call (`ctx.llm`), by default on the user's first fallback model. It reviews when someone asks to
merge (`auto_review: merge`, the default); the loop inside the agent's turn (review, bounce, fix, re-review, at most
`max_bounces`) is an option the user turns on (`finish`); `off` turns it off. A review is bound to the exact diff, so
the same diff never calls the model twice, and verified blocking findings refuse a merge.

**Why.** The deterministic gate cannot see a loosened assertion or an emptied test; a reviewer that did not write the
code can. Running it at merge by default keeps the cost to one review per change the person actually wants to land;
running it every turn is useful but spends the user's quota, so it is their choice.

**Alternatives.** The same model as reviewer (it shares the writer's blind spots; Foreman says so in the verdict when
it is the only model available). A review on every turn by default (cost the user did not choose). A review inside a
hook (a hook must answer fast and cannot wait on a model).

**Consequences.** What the model writes is printed on one line each and without control characters, so a diff cannot
make the review print text that reads as Foreman's own. See `docs/rules.md`, rules 8 and 16.
