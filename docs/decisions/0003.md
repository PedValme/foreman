# 0003 · A false-positive marker never passes alone, and the agent never merges

**Decision.** A finding marked `foreman:allow` is not a pass: it becomes NEEDS YOUR OK and waits for a person's
`/foreman allow`. An agent-run `gh pr merge` is always blocked; only a person's `/foreman merge` merges, after it
asks, and with nobody to ask it merges nothing. Refusals (BLOCKED, conflicts, draft) cannot be overridden.

**Why.** A marker the agent can write and that passes on its own is a switch the agent can flip to get its own change
through, which is exactly what Foreman exists to stop. The same goes for a merge: if the agent can merge, every
earlier check is advisory.

**Alternatives.** Trusting the marker (the agent waves itself through). An automatic merge when everything is green
(the person never sees the change; Hermes's catalog rules also forbid bypassing approvals).

**Consequences.** `allow` and `merge` exist only where the model cannot type them; a harness with no sound sign that a
person typed the command does not offer `allow` at all. See `docs/rules.md`, rules 3, 14, 18 and 24.
