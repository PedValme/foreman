# 0001 · The gate is a deterministic detector

**Decision.** What blocks a commit, a push or a pull request comes from a detector with no model: skipped or
isolated tests, deleted test files or files moved out of the tests, a changed check entry point, a bypassed hook and
secrets in the diff or in the pushed history. It uses only Python's standard library and git. A model review is an
optional second layer on top (0004), never what the gate depends on.

**Why.** The gate runs inside the agent's own loop, on every `git commit`, `git push` and `gh pr create`. It has to
answer in milliseconds, give the same answer twice for the same diff, work offline and without credentials, and be
something the agent cannot argue with. A rule over the diff does all four; a model does none of them reliably.

**Alternatives.** A model as the gate: slow, paid, non-deterministic and open to the diff steering it. Publishing a
GitHub check from the agent: the agent that wrote the code would be the one publishing its verdict, so the check is
not independent; that independence lives in CI (0011). Third-party dependencies for parsing: none was needed, and
every dependency is code that runs on the user's machine.

**Consequences.** The detector sees files and markers, not meaning: a loosened assertion or an emptied test is left
to the review (0004). See `docs/rules.md`, rules 1, 2 and 4.
